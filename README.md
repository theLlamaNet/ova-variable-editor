# OVA Variable Editor

**OVA Variable Editor** is a Python/Tkinter desktop tool designed to analyze, inspect, and modify variables within Jade Engine `.bf`, `.bin`, and `.ova` files (used in titles such as *Prince of Persia: The Sands of Time*, *Warrior Within*, *The Two Thrones*, *Rayman 4*, etc.).

Unlike ASCII parsers or generic hex editors, this tool structurally decodes Jade Engine records, enabling precise inspection and safe modification of boolean values without risking corruption of the name table or file layout.

---

## ✨ Key Features

* **Structural Parsing**: Recognizes 12-byte `AI_tdst_VarInfo` engine records and 30-byte editor name table slots.
* **Jade Big File (`.bf`) Support**: Directly indexes `.bf` File Allocation Tables (FAT) without requiring disk extraction.
* **Built-in LZO Support**: Automatically decompresses LZO-compressed blocks in standalone files like `Univers_oin_*.bin`.
* **Safe Value Editing**: The boolean edit controls (`00` / `01` - FALSE/TRUE) are enabled only when the value buffer (`pc_BufferInit`) is physically present.
* **Integrated Diff Tool**: Automatically compares two BIN dumps (e.g., *Cheats OFF* vs. *Cheats ON*) to instantly highlight modified bytes.
* **Hex Inspection**: Contextual 96-byte preview (48 bytes before, 48 bytes after) for every selected variable.
* **Jade Type Mapping**: Automatic type identification matching standard `AIdeftyp.h` types (float, int, object, network, etc.).

## ⚙️ How It Works

### 1. Import & LZO Decompression

Via **`Import .BF / .BIN`**, the tool accepts standalone binary dumps as well as full Jade Big Files (`.bf`). If a `Univers_oin_*.bin` file is wrapped in LZO compression (typical of retail PoP37/38), the application decompresses it in memory before analyzing.

### 2. Parsing Jade Engine Structures

The parser follows exact Jade source definitions:

* **Engine Records**: 12-byte serialized structures (`i_Offset`, `i_NumElem`, `w_Type`, `w_Flags`).
* **Name Table**: 30-byte fixed slots per variable.
* **Retail Fallback (`POP37/38 OVA`)**: In retail Big Files where name tables are omitted or obfuscated, engine records are still recognized and assigned synthetic labels (`OVA_###`) rather than falling back to random ASCII matching.

### 3. Jade Big File (`.bf`) Support

* **No Temporary Disk Extraction**: Directly indexes the `.bf` FAT (supporting linked FAT chains via `ul_NextPosFat`, tested on files with over 160,000 entries like `Rayman4.bf`).
* **Filtering & Search**: Built-in text filter to quickly locate `.ova`, `.bin`, and `.gao` entries.
* **Targeted Saving**: When saving edits on a `.bf` entry, a copy of the Big File is generated by replacing **only the target payload**, preserving exact file sizes and leaving compressed entries untouched.

### 4. Safe Boolean Editing

Unlike tools that guess offsets or overwrite string tables, **OVA Variable Editor** calculates the actual location within `pc_BufferInit`. Search and edit features (**`Search 00/01 candidates`**, **TRUE / FALSE** buttons) are locked unless the value buffer is verified present.

### 5. BIN Comparison (Diff Tool)

Using **`Compare with BIN…`**, you can load two dumps of the same file (such as before and after enabling cheats) to automatically map and display changed bytes.

## 🔍 Notable Use Cases

### Prince of Persia: The Sands of Time (SOT)

* Identifies key variable strings and metadata such as `mk_CheckPoint_CurKey`, `mk_Restart`, `mb_Cam_Invert_Rotation`, `mi_Tutorials`, `mb_DisplayUbiLogo`, and partial/truncated names.
* Accurately pinpoints structural changes between `SOT_CHEATS_OFF` and `SOT_CHEATS_ON` (e.g., the 17 differing bytes across `0x316..0x32B`).

### Rayman 4 (`Univers_oin_ff0c008e_RAYMAN4.bin`)

* Detects the Jade OVA description block at `0x6A3` by reading `sizeR = 108` (9 records) and the 270-byte name table.
* Correctly decodes 8 real variable names (`Territory_Path`, `Att_Protect_Gao_Dist`, `Mort_SeReleve`, `Item_Rafale`, etc.).
* Handles truncated buffers cleanly by explicitly indicating `truncated: 8/9 names` instead of fabricating missing records.
